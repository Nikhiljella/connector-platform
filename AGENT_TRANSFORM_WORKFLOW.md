# Agentic Transform Workflow — Requirements & Design

## What the User Asked For

> "Build a workflow type — first generates code, then builds the code, if failed give that build log to AI then fix it and redeploy until success, loop for X times. Then if success generate integration tests — fails then fix it, loop X times until successful, then deploy."

> "My transformation can be very huge logic — sometimes might need to make a call to external service."

---

## Core Insight: Transforms Are Code, Not Config

Simple field ops (rename, cast, pick) stay as JSON config in `transformEngine.js`.
But complex transforms — multi-step logic, external API calls, conditional branching — need to be **real JavaScript functions** generated by AI and executed in a sandbox.

Two-tier transform system:
```
Tier 1: Config transforms  (existing transformEngine.js)
  → rename, pick, cast, timestamp, template
  → stored as JSON ops array in connectors.transforms
  → safe, synchronous, in-process

Tier 2: Code transforms  (new — AI-generated JS)
  → arbitrary async logic, external service calls
  → stored as JS function string in connectors.transform_fn
  → executed in a sandboxed worker with controlled fetch access
```

Tier 1 runs first, then Tier 2 runs on the output. User can use either or both.

---

## User-Facing Trigger

In the onboarding wizard **Step 4: Transforms**, the user:
1. Types plain English instructions per field — can be simple or complex:
   - `dob` → `"convert date from MM/DD/YYYY to ISO 8601"`  ← Tier 1 (cast)
   - `address` → `"call Google Maps API to normalise and geocode this address"` ← Tier 2 (code)
   - `nationalId` → `"validate against our internal KYC service at https://kyc.internal/validate, set status=rejected if invalid"` ← Tier 2 (code)
2. Clicks **"Generate with AI"**
3. Watches a real-time agent pipeline run (SSE — same pattern as onboarding)

## Agentic Workflow — 5 Phases

```
Phase 1: Classify
  └─ AI reads all field instructions
  └─ Decides per field: Tier 1 (config op) or Tier 2 (code)
  └─ Simple ops → ops array; complex/external → code function

Phase 2: Generate
  └─ Tier 1: AI outputs transforms[] JSON array (existing ops)
  └─ Tier 2: AI outputs async JS transform function
             signature: async function transform(record, { fetch, env }) { ... }

Phase 3: Build Loop  (max N attempts, default 3)
  └─ Tier 1: dry-run through transformEngine.js on sample data
  └─ Tier 2: execute function in sandbox with sample data + mock external calls
  └─ Check: no runtime errors, output has expected fields, types correct
  └─ PASS → go to Phase 4
  └─ FAIL → send { error, code/ops attempted, original instructions } to AI → fix → retry

Phase 4: Test Loop  (max N attempts, default 3)
  └─ Fetch live data from connector URL
  └─ Run full transform pipeline (Tier 1 + Tier 2) on real records
  └─ Assert: required fields non-null, schema match, no errors
  └─ External service calls: use real endpoints (or mock if flagged by user)
  └─ PASS → go to Phase 5
  └─ FAIL → send { test output, failure reason } to AI → fix → retry

Phase 5: Deploy
  └─ Save Tier 1 ops to connectors.transforms
  └─ Save Tier 2 function to connectors.transform_fn
  └─ Activate connector (status = active, start cron job)
```

## Generated Code Contract

AI generates a function with this exact signature:

```js
async function transform(record, { fetch, env }) {
  // record — the raw API record after Tier 1 ops applied
  // fetch  — sandboxed HTTP client (same API as node-fetch)
  // env    — connector-level env vars (API keys, service URLs, etc.)

  // Example: call external KYC service
  const kyc = await fetch(env.KYC_SERVICE_URL + '/validate', {
    method: 'POST',
    headers: { 'Authorization': `Bearer ${env.KYC_API_KEY}` },
    body: JSON.stringify({ nationalId: record.nationalId }),
  });
  const result = await kyc.json();

  return {
    ...record,
    status: result.valid ? 'active' : 'rejected',
    kycScore: result.score,
  };
}
```

Rules enforced:
- Must be async, must return the transformed record object
- Only `fetch` and `env` are injected — no `require`, no `process`, no `fs`
- Timeout: 10 seconds per record
- No side effects outside of returning the record

## Sandbox Options (Execution Environment)

The generated function cannot run directly in the main process — it's AI-generated code.

| Option | Isolation | External calls | Complexity | Recommendation |
|--------|-----------|---------------|------------|----------------|
| `node:vm` | Weak (same process) | Blocked by default | Low | ❌ Not enough for external calls |
| `worker_threads` + `vm` | Medium (thread boundary) | Controlled via message passing | Medium | ✅ Good for most cases |
| `child_process.fork` | Strong (separate process, killable) | Full network access (controllable) | Medium | ✅ Best default choice |
| **E2B** (e2b.dev) | Full OS sandbox (cloud) | Yes, full network | Low (SaaS) | ✅ Best if you want zero infra |
| Docker container | Full isolation | Yes, full network | High | For production hardening later |

**Recommended: `child_process.fork` for now, E2B when hardening for production.**

`child_process.fork` gives:
- Separate Node process — crash doesn't take down the platform
- Killable with timeout (kill after 10s)
- Full network access for external service calls
- No extra infrastructure

## Retry Context — What Gets Sent Back to AI

Each retry includes increasingly rich context so the model doesn't repeat mistakes:

```
ATTEMPT: 2 of 3

ORIGINAL INSTRUCTIONS:
  nationalId → "validate via KYC service, set status=rejected if score < 0.8"

SAMPLE DATA:
  { nationalId: "ZA123456", ... }

PREVIOUS CODE:
  async function transform(record, { fetch, env }) {
    const res = await fetch(env.KYC_URL + '/check', ...);  // ← this line failed
    ...
  }

ERROR:
  TypeError: Cannot read properties of undefined (reading 'json')
  at transform (sandbox:4:28)
  Hint: fetch returned non-2xx status (401 Unauthorized) — check env.KYC_API_KEY

FIX THE CODE. Return only the corrected function, no explanation.
```

## Agent Pipeline Steps (SSE real-time)

| Step | Agent | Does |
|------|-------|------|
| 1 | **ClassifyAgent** | Analyses all instructions, decides Tier 1 vs Tier 2 per field, builds prompt plan |
| 2 | **GenerateAgent** | Claude API call → Tier 1 ops JSON + Tier 2 JS function |
| 3 | **BuildAgent** | Runs both tiers on sample data in sandbox; AI fix loop ≤ N times |
| 4 | **IntegrationTestAgent** | Fetches live data, runs full pipeline, asserts output; AI fix loop ≤ N times |
| 5 | **DeployAgent** | Saves to DB, activates connector |

---

## AI Model Strategy

| Phase | Model | Why |
|-------|-------|-----|
| Classify | `claude-haiku-4-5` | Simple classification, fast |
| Generate (Tier 1 ops) | `claude-haiku-4-5` | Structured JSON, well-defined schema |
| Generate (Tier 2 code) | `claude-sonnet-4-6` | Complex code generation, external service logic |
| Fix loop | `claude-sonnet-4-6` | Needs reasoning about runtime errors and API contracts |

## Data Stored

```sql
-- New column on connectors table
ALTER TABLE connectors ADD COLUMN transform_fn          TEXT;  -- AI-generated JS function string
ALTER TABLE connectors ADD COLUMN transform_instructions TEXT; -- user's plain English (JSON)
ALTER TABLE connectors ADD COLUMN transform_env          TEXT; -- env vars for external services (JSON, encrypted at rest)
```

`connectors.transforms` (existing) — Tier 1 config ops:
```json
[
  { "op": "pick",   "fields": ["id","name","email","dob","nationalId","address"] },
  { "op": "rename", "from": "id",   "to": "partyId" },
  { "op": "rename", "from": "name", "to": "fullName" },
  { "op": "timestamp", "field": "dateOfBirth", "format": "YYYY-MM-DD" }
]
```

`connectors.transform_fn` (new) — Tier 2 generated code:
```js
async function transform(record, { fetch, env }) {
  const kyc = await fetch(`${env.KYC_URL}/validate`, {
    method: 'POST',
    body: JSON.stringify({ id: record.nationalId }),
    headers: { Authorization: `Bearer ${env.KYC_API_KEY}` },
  });
  const { valid, score } = await kyc.json();
  return { ...record, status: valid ? 'active' : 'rejected', kycScore: String(score) };
}
```

`connectors.transform_instructions` (new) — user's original instructions, preserved for re-generation:
```json
{
  "dob":        "convert date from MM/DD/YYYY to ISO 8601",
  "nationalId": "validate via KYC service at env.KYC_URL, set status=rejected if score < 0.8",
  "address":    "call Google Maps Geocoding API, normalise to street/city/country"
}
```

## Aggregator Execution — How Transforms Run Each Pull

```
connector_data_N (raw record)
       ↓
  applyTransforms(record, connector.transforms)   ← Tier 1: sync, in-process
       ↓
  runInSandbox(connector.transform_fn, record)    ← Tier 2: async, forked process
       ↓
  party_objects / account_objects (final merged row)
```

Each Tier 2 execution: fork → run with timeout → collect result → kill process.
If Tier 2 fails on a record: log error, keep Tier 1 output, mark record with `transform_error`.
